### Day 2606: Backups Roll Off

Today I learned that a roll-off on storage systems is like a type of policy that determines in which situations a backup needs to be deleted for some events. Imagine that you are running out of physical hardware space, so you have a roll-off policy that in a situation in which the used capacity is greater than 98%, the hardware automatically removes the latest backup, to make room for a new one.  Another example can be a policy that deletes oldest backups after X days have passed. This word was new for me and looks like it is something old, used on mainframe environments.

### Day 2605: jaxb-core Library

Today I learned how to use the jaxb-core library within a Java application. The jaxb-core library is an Eclipse implementation used to serialize (marshal) and deserialize (unmarshal) data between Java objects (DTOs) and XML files. jaxb-core is an implementation library that follows the jakarta.xml.bind Java API specification. Typically, developers do not need to depend on jaxb-core directly; instead, they declare dependencies like jaxb-runtime, which brings in the core library as a transitive dependency so build tools like Maven can manage their lifecycles automatically. I built a basic Java application to practice serializing and deserializing Java objects to XML content and vice versa. I used the JAXBContext, Marshaller (marshal()), and Unmarshaller (unmarshal()) APIs from the Jakarta library to perform these operations. Finally, I executed the application directly from the terminal using the java command. It was interesting to discover that 6 separate libraries were required to run this exercise due to the modular design and enterprise activation dependencies of the Jakarta standard.

### Day 2603: Storage Concepts

Today I practiced storage backup concepts, including Source Volume, Recovery Volume, Backup Frequency, and Restore Action. A `Source Volume` is the designated volume we want to back up; it may contain production database data from which we create multiple point-in-time copies as backup tasks. A `Recovery Volume` is the target volume where we recover the snapshot data. The `Restore Action` is the final step of writing the snapshot data back to the Recovery Volume so it can be used as the new production data. Finally, `Backup Frequency` is the scheduled interval for taking snapshots of the volume—for example, a 1-hour interval means backups run every hour.

### Day 2601: Retention Period

Today I was learning what is and how to configure the retention period of a backup copy-in-time of a volume. A copy-in-time is a copy of the current state of a volume in a exact moment. The retention period is a configuration property for the software that manages the backups that configures for how much time or number of copies you want to keep that backup like hours, days, of 100 backups. Normally there is an another software property to remove backups automatically when the storage system does not have enough space to continue creating backups, this property can be configured like last backup or first backup, it depends on how the software works.
